# فحص MoOS السحابي وإصلاح عرض التطبيقات — 10 نوفمبر 2026

أُصلح خلل VS Code الذي كان يرسم محتواه داخل جزء أصغر من الإطار المكبّر. الإصلاح يعمل داخل البرنامج المثبّت مع الحفاظ على شاشة 1280×720 ونسبة 75% التي اختارها المالك. رفض المالك تكبير الواجهة في المراجعة الأولى، لذلك أُلغي التكبير الإضافي: القيمة الحالية للتكبير صفر وحجم نص المحرر والطرفية 14، مع بقاء نسبة النظام 75%. صار المساران الموجودان للفتح من الاختصار والمتجر يحملان إصلاح الرسم نفسه. أُخفيت لوحة المخرجات الفارغة من أمر VS Code الأصلي لتصبح مساحة المحرر بارتفاع النافذة المتاح. نُفذ الأمر عبر مسار الإدخال الأصلي للجلسة بعد فحص اسم الأمر ونتيجته بصرياً؛ لم تُمس الحافظة أو ملفات المشروع. أصبح تشغيل أدوات MCP التي يديرها المحرر عند الطلب. النسخ الأصلية محفوظة للرجوع. هذه إعدادات محلية؛ ليست تحديثاً جديداً لصورة النظام.

## النتائج المثبتة

- النظام العامل هو MoOS 911 الموقّع، مع 908 للرجوع. لم تُعد تشغيل جلسة سطح المكتب أو خدمات الاتصال في هذا الفحص.
- متجر MoOS لا يعرض تحديثات معلّقة. اكتمل تشغيل تحديث المستخدم وتحديث تطبيقات النظام، ونجح فحص سلامة 55 مكوّناً للمستخدم و35 للنظام.
- VS Code 1.145.2 يطابق الإصدار المستقر الرسمي المتاح لهذا المعمار. حُدثت إضافة Claude إلى 2.1.322، وحُفظت إضافات التوافق المثبّتة على إصدارات محددة. واجهة Codex التي كانت تفشل فتحت في الملف الشخصي الحقيقي، وسجّلت بدءاً ناجحاً.
- انتهى فحص القرص الشامل بالقراءة فقط خلال 32 دقيقة و27 ثانية، بحجم 134.10 GiB ودون أخطاء. عدادات أخطاء القرص الخمسة صفر، ومساحة متاحة تقارب 57 GiB. أُعيد حد سرعة الفحص المؤقت إلى حالته الأصلية.
- نجح فحص MoOS الأصلي: 52 اختباراً وملاحظتان. لا توجد خدمات فاشلة حالياً. فحص ما بعد التحديث أبقى فشلاً تاريخياً واحداً من تعطّل أداة فحص الشاشة داخل بيئة التنفيذ المعزولة في هذه المحادثة؛ التشغيل في الجلسة الصحيحة نجح. لم يُمسح السجل أو يُضعف الاختبار.
- في عينة أخيرة مدتها 30 ثانية مع Code وChatGPT وأدوات التطوير والاتصال والخدمات: نحو 6 GiB ذاكرة متاحة وضغط ذاكرة لحظي صفر. هذه ليست مقارنة أداء مضبوطة أو وعداً بزوال كل بطء.

## المراجعة البصرية وحدودها

راجعت نوافذ التطبيقات التسعة المثبّتة عبر Flatpak: الحاسبة، GIMP، Krita، LibreOffice، Curtail، Chrome، Chromium، Ptyxis وVLC. وراجعت VS Code والمتجر وصفحة ضبط الشاشة الأصلية، مع التحقق من تحميل مكتبة الشاشة المثبّتة تحت `/usr`.

فتح GIMP صورة اختبار باسم عربي، وفتح VLC فيديو اختبار محلياً وعرض إطاراته. أُغلقت شاشة ترحيب GIMP من زرها الأصلي وأُوقف تكرارها عند البدء؛ يمكن إعادتها من المساعدة. اكتمل إعداد VLC للاستخدام المحلي مع رفض الجلب التلقائي لبيانات الوسائط من أطراف خارجية. أُغلقت نوافذ المراجعة طبيعياً، وبقي Code وChatGPT.

بقيت المحاولات الأولى محفوظة: ظهور نافذة عدم استجابة عند إغلاق GIMP، وصور محجوبة بنافذة أخرى لم تُقبل كنجاح، ومحاولة إدخال في الحاسبة لم تثبت النتيجة المطلوبة. نجاح ظهور النوافذ لا يثبت جميع وظائف كل برنامج أو اللمس الفعلي عبر الهاتف.

المحفظة بقيت مطفأة بحسب اختيار المالك؛ تحذير حفظ بيانات الدخول في Code لم يُخفَ ولم يُستبدل بتخزين غير مشفّر. الإصدارات البعيدة لتطبيق Codex المكتبي لم يمكن التحقق منها عبر محدّث Linux. لم يُختبر تسجيل الدخول إلى كل الخدمات أو جميع وظائف التطبيقات الـ42 الظاهرة في المتجر، ولا اكتمال تعريب البرامج الخارجية.

لم يُحذف أي ملف شخصي أو صورة بناء أو ذاكرة مخبأة في هذه المحادثة. مسح أحجام المجلدات الكامل تجاوز حدّه الزمني؛ أرقامه جزئية. جميع صور البناء الـ55 المرتبطة بالاستعمال أو الاستعادة محفوظة. فحص القرص الشامل المكتمل منفصل عن هذا الإحصاء الجزئي.

أكد المالك أن النسخة المكبّرة كانت أكبر من المطلوب؛ هذه ملاحظة رفض محفوظة وليست قبولاً. طُبّق بعدها تصغير الواجهة إلى قياسها الطبيعي، وتأكيد النسخة النهائية على الهاتف ما زال غير متوفر. الرسوميات هنا برمجية على خادم ARM بمعالجين افتراضيين؛ لا يمثل هذا فحص GPU أو قرص مادي أو قبول Windows/Android.
