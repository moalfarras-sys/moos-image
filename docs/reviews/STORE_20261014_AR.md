# مراجعة Mo Store على محطة NVIDIA

هذه مراجعة لعمل جارٍ، وليست إعلان اكتمال المتجر. الخطة الوحيدة هي
[DEVELOPMENT_PLAN.md](../DEVELOPMENT_PLAN.md)، وخصوصًا A3 وP4.1 وP4.4.

راجعت نسخة محطة NVIDIA الفعلية عند `93a9019e3a6d4268a725f89030c0685992c00a25`:
الفرع نظيف، ويضم 26 التزامًا بعد نسخته البعيدة. حُفظت هذه الالتزامات في
[فرع مراجعة مستقل](https://github.com/moalfarras-sys/moos-image/tree/audit/nvidia-store-snapshot-20261014)
دون تعديل فرع المحطة أو مساحات عملها. واجهة `store/ui-split` كانت تعمل بالتوازي؛
لقطة التصيير تضم 20 ملف QML عند `e0ca45b1` مع تعديل غير ملتزم في `main.qml`.
اللقطة ليست آخر عمل العامل، ولا واجهة مثبتة من إصدار موقّع.

## ما أصبح موجودًا في المصدر

الفهرس الجديد يضيف الكلمات المفتاحية العربية والإنجليزية، معلومات الجهاز والتوافق،
وثائق التفاصيل، التطبيقات المحلية والتطبيقات التي اختفت بياناتها من الكتالوج.
الخلفية تضيف أنواعًا متعددة وأفعال تثبيت وتشغيل وحذف وتحديث وصلاحيات وراء
`moos-storectl`. هذه إضافات حقيقية، لكن ربط كل أجزائها واختبارها لم يكتمل.
الفهرس المثبت قبل هذه الدفعة كان يحوي 3,397 تطبيقًا على NVIDIA و2,934 على Oracle؛
الكتالوج المنسق في اللقطة ما زال 53 مدخلًا. العدد لا يثبت توافق كل برنامج.

## نتائج قابلة لإعادة الاختبار

اختبارات الملفات والتحديثات استخدمت منازل وحالة XDG خاصة وأدوات وشبكة اختبار؛
لم تُحذف تطبيقات المالك أو ملفاته، ولم يُشغّل برنامج ناشر.

| المسار | النتيجة عند المصدر المراجع |
| --- | --- |
| إعادة محاولة RPM بعد انقطاع تبديل المجلدين | قد تحذف النسخة السابقة العاملة قبل نجاح قراءة الشبكة؛ المحرك نفسه لم يُربط بعد بالكتالوج أو سلطة المتجر |
| حذف برنامج Windows مع إبقاء البيانات | يحذف مستندًا داخل البيئة الخاصة بالبرنامج |
| حذف مجلد Windows بلا سجل أو مشغّل MoOS | يتبنى المجلد اليدوي ويحذف ملفه |
| فشل إعادة التسمية الثانية في تحديث Windows | يترك النسخة العاملة في المجلد السابق دون مسار التشغيل |
| إعادة محاولة Windows مع فشل التنزيل | لا يعيد النسخة العاملة أولًا |
| سجل Android الذي تكتبه الخلفية | الفهرس لا يقرأ نسخته، فلا يعرض التحديث؛ التطبيقات المثبتة من ملفات غير مدرجة لا تدخل الجرد نفسه |
| الاختبارات على ARM | `just check` يفشل في اختبار الكتالوج الذي يتوقع تطبيق Windows مخصصًا لـx86؛ يجب عزل معمارية الحالة الاختبارية، مع إبقاء التصفية الحقيقية |

جهزت رقعة حفظ الملفات والتعافي، في نسخة خاصة فقط: خمسة اختبارات متطابقة تفشل
مع المصدر القديم وتنجح مع الإصلاح. مجموعة RPM تنجح في 76 اختبارًا؛ مجموعة
Windows تنجح مع تخطي اختبار التشغيل الحقيقي الاختياري. `git apply --check`
ينجح عند اللقطة. الدليل: [اختبارات السلامة](../releases/2026-10-14-store-install-safety-review.json).
هذه الرقعة تحفظ بيانات البيئة الخاصة؛ سياسة الملفات التي يحتفظ بها برنامج محمول
بجوار تنفيذيته تحتاج قبولًا منفصلًا. لم تُدمج الرقعة ولم تُشحن.

رقعة الجرد الخاصة تقرأ إيصال Android الذي تكتبه الخلفية، وتعرض التحديث حسب
بصمة الملف وتحتفظ بالتطبيقات المثبتة من ملفات؛ وتصحح افتراضات اختبارات ARM
دون توسيع قبول الإنتاج. 111 اختبارًا تنجح، والضوابط الجديدة تفشل بالمصدر القديم.
[الدليل](../releases/2026-10-14-store-index-review.json).
Windows يحتاج أيضًا مطابقة السجل بمجلد التطبيق ومسار تشغيله، لا اعتبار
وجود JSON وحده تثبيتًا؛ ذلك لم تُصلحه رقعة Android.

## الواجهة والبحث

شُغلت لقطة الواجهة بمحرك Qt الأصلي على ARM، بحافلة ومجلدات خاصة، وبرسم برمجي
معزول وسلطة التثبيت معطلة. خمس صور عربية وإنجليزية خرجت بلا خطأ QML، لكن
الفحص الفعلي أثبت أن أنواع Windows والويب والملفات المحلية لا تملك التشغيل
والإزالة عبر الواجهة بعد، وأن تطبيقًا غير موثق يحصل على علامة «موثّق».
البحث يتجاهل حقل الكلمات المطبع في الفهرس، واختصار صفحة التحديثات يفتح
الاستكشاف، وتحديث التطبيق المثبت من كتالوج يصنّف كمكوّن مشترك.

التصيير عند 900×620 وخط 20 نقطة يُظهر تداخل البطاقات؛ عند الخط الافتراضي
يُقصّ أسفل البطاقة الرئيسية. يلزم اشتقاق ارتفاع البطاقة والشريط من المحتوى
والخط، وربط الأفعال والمعلومات بالفهرس والخلفية قبل قبول المظهر الجديد.
اللقطة العادية ليست دليلًا على سهولة الاستخدام عند تكبير الخط.
الدليل: [مراجعة Qt](../releases/2026-10-14-store-ui-review.json).

قراءة التوافق من سياق المستخدم الرسومي الفعلي على NVIDIA تنجح في 96 مللي ثانية
وبذروة 21.2 MiB: RTX 2080 SUPER، 16 خيط معالجة، 16.6 GB RAM، جلسة Wayland
وشاشة 3840×2160 بمقياس 250%. Android مهيأ لكنه متوقف عند الفحص، وبرسم برمجي؛
محرك Windows جاهز للـ64 بت، لا للـ32 بت. هذه قراءة جاهزية وليست تجربة التطبيقات
أو إثبات تسريع Android. Oracle يعرض Linux فقط. لا تُحسب النتائج من قشرة SSH
كقيم جلسة رسومية: قراءتها الأولى تركت `session=null`، ثم أثبت سياق المدير
الرسومي الحقيقي `session=wayland` دون تعديل البيئة أو المضيف.

## الدمج وتسليم الإصلاحات

ملفات المتجر محجوزة للعامل الجاري على NVIDIA في
[جدول التنسيق](https://github.com/moalfarras-sys/moos-image/blob/feat/mo-store-library-20261014/docs/AGENT_COORDINATION.md).
قاعدته: “If you need a file another agent holds, say so in your row and wait for their
merge instead of editing it.” لذلك تبقى الإصلاحات والضوابط في حزمة مراجعة خاصة؛
لا تتداخل مع ملفات العامل. مراجعة Oracle تحجز تقريرها وأدلتها فقط، وتطلب
دمج إصلاحات السلامة والجرد وربط الواجهة قبل قبول دفعة المتجر.

مرشح الإصدار الجاري مستقل وثابت عند `5745edd1`؛ لا يحتوي هذه الدفعة.
ترقية المتجر تحتاج بوابات المصدر، بناء الصورة، إثباتات الإقلاع والتثبيت
والتوقيع ثم قبول NVIDIA الفعلي. وجود محرك Windows أو Android لا يثبت تهيئته
أو توافق كل التطبيقات. واجهة API/MCP مستقبلية تستعمل سلطة الأفعال نفسها،
ولا تنشئ مسار تثبيت آخر.
