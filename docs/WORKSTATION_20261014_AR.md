# فحص محطة التطوير — 2026-10-14

هذا فحص فعلي على Oracle ARM وقراءة منفصلة لجهاز NVIDIA. وجود إضافة أو
تسجيل دخول محفوظ لا يثبت كل وظائفها أو صلاحية كل اشتراك وحصة API.

## VS Code وأدوات التطوير

- Oracle: VS Code 1.139.1 ARM64، خمسون إضافة مثبتة. NVIDIA: الإصدار نفسه
  و35 إضافة. لم يُعد تشغيل محرر المالك أو تُحذف إضافاته.
- خطأ QML الأصلي مثبت: الخادم الذي حمّلته الإضافة يخرج 127 بسبب
  `libmysqlclient.so.21`. خادم Qt 6.11.2 في SDK الحالي يعمل.
- وسيط Toolbox الأول اجتاز بروتوكول التحليل، لكنه تجاوز مهلة ثانية واحدة
  في الإضافة الفعلية. حُفظ هذا الإخفاق. الوسيط الأسرع وSDK محلي صغير
  مطابقان لحزمة Qt؛ بدء الخادم داخل الإضافة نفسها نجح. السكربت
  `scripts/workstation-qmlls.sh` يرفض اختلاف حزمة Qt، ويحافظ على stdio
  ويترك بناء CMake إجراءً صريحًا.
- اختبر الخادم ملف QML صحيحًا بلا تشخيصات، ثم اكتشف خاصية خاطئة عمدًا.
  رفض كذلك manifest بحزمة Qt مختلفة بخروج 69، وشغّل الخادم الحقيقي عند
  تطابق الحزمة. اختبارات الإصدار تستخدم SDK خاصًا ولا تعدّل نسخة المالك.
  النسخة المحلية تحتوي فقط على الخادم ومكتبة المترجم؛ النظام الثابت سليم.
- NVIDIA: الخادم الذي حمّلته الإضافة فشل بسبب `libodbc.so.2`؛ SDK
  المستخدم المطابق نجح على المضيف وداخل Flatpak وفي تحليل QML الصحيح
  والخاطئ. سُجّل مساره في المحرر، لكن بدء الإضافة في workspace المالك
  نفسه لم يُرصد بعد؛ لا تُعد نتيجة البروتوكول قبولًا لتلك الجلسة.
- أُنشئ ملف Vim المفقود فقط بصيغة الإضافة الحقيقية
  `{"version":"1.0","registers":[]}` دون استبدال ملف موجود.
- GitHub 0.168 لا يتوافق مع VS Code 1.139.1. محاولة تثبيته رفضها المحرر؛
  بقي الإصدار المتوافق 0.166.1. حزمة VS Code المثبتة تطابق آخر commit
  المتاح من Flathub عند الفحص؛ لا يُفرض إصدار إضافة غير متوافق.
- تغيّر اسم طرفية SDK إلى **MoOS SDK** مع الحفاظ على أمرها وإعداداتها.
- سجل بدء المحرر أظهر أخطاء جلب قائمة OpenRouter والتحقق من بيانات
  Vercel AI Gateway في إضافات Roo/Cline. محاولة تحديث كل منهما أعادت
  «مثبتة مسبقًا» دون تغيير؛ هذه المسارات لم تُقبل وظيفيًا بعد.

## SDK: اختبارات تنفيذ، لا جرد ملفات فقط

| المكوّن | النتيجة المقاسة |

| C++23 | بناء داخل SDK وتشغيل الملف الناتج على مضيفي ARM وx64 |
| Go وRust | بناء/تنفيذ برامج اختبار خاصة على الجهازين، دون تغيير مشاريع المالك |

| Flutter 3.47.4 / Dart 3.13.3 | تحليل واختبار widget وبناء Linux ARM وx64 نجحت على الجهازين بالإصدار المعتمد نفسه |
| GTK وmpv وGDB | أضيفت تبعيات التطوير داخل حاوية SDK للمستخدم؛ لا حزم على النظام الثابت |

بداية `pub get --offline` فشلت لأن ذاكرة الحزم لا تحتوي `flutter_lints`؛
حُفظ الإخفاق واكتمل الجلب المعتاد، ثم التحليل والاختبار والبناء. الملفات
والحزم الناتجة تخص مشروع اختبار خاصًا، وليست تغييرًا لمصدر MoPlayer.
SDK Flutter مسجّل في VS Code وفي أوامر المستخدم. NVIDIA لديه مسبقًا
Flutter 3.47.4 و.NET 10.0.401؛ هذا الجرد لا يثبت بناء جميع المشاريع عليه.
اختبارات NVIDIA اللاحقة نفذت 11 أمر SDK، والتحليل والـwidget والبناء
لـFlutter. محاولة `podman exec` الأولى رفضت حاوية SDK المتوقفة؛ تشغيلها
عبر Toolbox أصلح شرط التشغيل، وبقي الخطأ محفوظًا. أول fixture Java افترض
JDK إضافة غير موجود؛ استُخدم JDK الحاوية بدل ذلك. هذه إخفاقات تهيئة
الاختبار، وليست نتائج ناجحة يُخفيها التقرير.

## MCP والحسابات

المرجع يبقى خوادم المستودع الأربعة. أضيفت إسقاطاتها المحلية إلى إعداد
Codex وملف MCP الخاص بـVS Code، مع حفظ الإعدادات السابقة وعدم تغيير
النموذج أو الأذونات أو مزوّد المالك. `codex mcp list` يقرأ الخوادم الأربعة.
تسجيل الإعداد لا يعني أن كل جلسة مفتوحة أعادت اكتشاف الأدوات.
على NVIDIA بقي `node_repl` وإعدادات Codex الأصلية كما كانت؛ CLI يقرأ
الخوادم الأربعة إضافة إليه. الخوادم المحلية وContext7 وبحث Qt نجحت
هناك أيضًا. إعداد Context7 الافتراضي مجهول ولا يفرض مفتاحه الاختياري.

| الخادم | الاختبار الفعلي |

| sequential-thinking | initialize/tools/list وطلب تفكير خاص واحد |
| Chrome DevTools 1.10.1 | initialize/tools/list وlist_pages بمتصفح معزول |

لا تثبت كل حصص الاستدلال المدفوع أو حسابات الإضافات الاختيارية؛ لم تُقرأ
كلمات مرور أو مفاتيح خاصة. قيود معاينة Vercel السابقة ليست نتيجة نجاح.

## النظام وNVIDIA

Oracle يقلع على .775 الموقّع، و.NET/QML/Flutter/MCP لم تغير أصل النظام.
عينة cgroup لمدة 20 ثانية أثناء الفحص سجلت KWin نحو 2.50% من نواة
وPlasma نحو 0.36%؛ الذاكرة المتاحة نحو 6 GiB. هذه عينة عمل محدودة،
وليست إثبات خمول أو تحمل طويل. helper الإدخال يشترك في cgroup خدمة
Remote، ولا يُجمع استهلاكه معها مرة ثانية.
NVIDIA يقلع على .1044، boot ID `5cf457a9-75d6-4ed6-9376-fe392244145d`:
55 فحص نظام و55 فحص بعد التحديث نجحت، و18 بصمة وMoPlayer تطابق المصدر.
جلسة `plasmalogin` Wayland واحدة وتعريف NVIDIA يطابق النواة 7.2.9.

آلية التحديث الرسمية جهزت .1046 بالدجست
`0235cad7d5da41af9df25355f7b7beb395893db66e56f9bc5b5b514365579739`.
قراءة OSTree أثبتت 19 ملفًا وMoPlayer مطابقين. هذا **stage**، وليس إثبات
إقلاع .1046. أزيلت فقط حزمة اختبار greeter القديمة: 124,296,811 بايت
منطقيًا، بعد تطابق البديل وعدم وجود process/FD يستخدمها واختفاء override.
لم يُقَس لها توفير مادي مستقل، ولم تُمس PIN/TLS أو بيانات المالك أو rollback.

المتبقي في الخطة: KVM غير متاح على Oracle، ومساحة العمل أقل من تقدير
60 GiB لبناء صور/VM كبيرة؛ اختبارات جميع الإضافات والحسابات والحصص،
إقلاع NVIDIA .1046 والتحمل وإمكانية الوصول والأجهزة المتنوعة تبقى منفصلة.
الأدلة الخاصة والنسخ الاحتياطية في `.cache/moos-workstation-audit-20261014`؛
الإعدادات المحتوية على معلومات حساب المالك لا تدخل المستودع.

إعادة تشغيل البوابات سجلت إخفاقًا في
`ARealFolderListModelSeesTheRename.test_a_lingering_failure_never_speaks_for_a_success`:
لم يصل إشعار بدء المهمة خلال 10 ثوانٍ. 15 تجربة تشخيص معزولة لاحقة
نجحت؛ أظهرت أن `probe-ready` يسبق جاهزية FolderListModel. هذا قياس
لتوقيت fixture، وليس إثبات سبب الإخفاق أو إصلاح المنتج. لم يتغير
الاختبار أو Island أو المنتج، ويبقى الإخفاق الأول محفوظًا.
