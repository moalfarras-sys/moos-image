# فحص السحابة والموارد — 13 أكتوبر 2026

النظامان المقاسان هما Oracle ARM `.763` وNVIDIA `.1032` الموقّعتان، من المضيفين الفعليين.
العمل المتبقي في [DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md) وحدها.

## الذكاء السحابي الفعلي

كان `/healthz` يعلن سياسة تكلفة paid، لكن `/route` كشف أن النموذج المحفوظ
`openrouter/free`. اختيار مزوّد يسمح بالمدفوع لا يجعل النموذج المجاني مدفوعًا.
بوابة MoOS تضيف حدود السعر الصفرية لكل نموذج مجاني؛ لم يتغير اختيار المالك
ولم يُقرأ مفتاح أو ملف مزوّد أو تُرسل ملفات/سياق خاص أو تُطلب إجراءات.

- الرد المباشر الاصطناعي عاد HTTP 200 خلال 1.011 s من
  `nvidia/nemotron-3-super-120b-a12b:free`، 68 token، وتكلفة مسجلة صفر.
- بث SSE عاد HTTP 200، وأول نص خلال 1.279 s، و12 حدثًا ثم DONE؛ التكلفة صفر.
- طلب جلسة اختبار منفصلة عبر الوكيل عاد HTTP 200 مع `X-MoAI-Agent=hermes`
  خلال 9.236 s، ولم يكن مجرد liveness أو direct fallback. بدأ العامل
  الموجود أصلًا عند الطلب؛ قُرئت له نحو 201 MiB بعد الرد. هذا عامل محادثة
  سحابي، لا نموذج محلي أو عملية GPU. لا inference محلي ظاهر في pgrep.

هذه تجارب النص الموجودة على حساب المالك، لا إعداد حساب جديد أو إثبات الصوت
والحصص وكل أدوات الوكيل. لم يُقَس سعر طلب Hermes من usage غير الموجود؛ حد
النموذج المجاني تؤكده بوابة المصدر، ونتيجته تثبت رحلة الوكيل المحددة فقط.

## الموارد وتكامل سطح المكتب

عينة native مدتها 30 s تقرأ أوراق cgroups حتى لا تضيف الآباء والأبناء مرتين.
نافذتا Code نحو 5.1 GiB في cgroup، منها قرابة 2.2 GiB file cache و2.9 GiB
anonymous؛ لذا الرقم كله ليس RAM دائمة غير قابلة للاسترداد. استهلاكهما
10.24 و5.30% من نواة. KWin 5.99%، plasmashell 0.25%، privacy 0.05%.
خدمة موصل السحابة نحو 23 MiB. ضغط RAM صفر؛ PSI CPU avg10=3.67.

حساب Remote يجب أن يشمل `app-org.moos.remote-*.scope` المنفصلة، لا خادم
.NET وحده. اتصالات TCP قد تكون status/control ولا تثبت صورًا أو كلفة GPU.
تُحفظ التفاصيل محليًا في `test-results/runtime-audit/`، ولا تُنشر مسارات
المالك أو بياناته. هذه عينة عمل مع المحرر والخدمات، لا benchmark خمول أو WAN.

قراءات فعلية: جلسة Wayland، KWin وplasmashell، شاشة افتراضية 1280×720@60
و100%، UI2 Nova وديكور MoOS، GTK Breeze الذي يتلقى ألوان النظام، ومدخل
D-Bus واحد للبوابة `org.freedesktop.portal.Desktop`. وجود KDE وGTK backend
ليس نافذتي إعدادات: البوابة تختار implementation لكل واجهة. لا تبديل أو
إعادة تشغيل للـRemote/portal/compositor، ولا consent جديد أو إغلاق محرر المالك.

## الإصلاحات تحت التطوير

مسار proxy كان يترك إغلاق الرد upstream للـreference counting. الاختبار
الجديد يحتفظ بالرد ويشغّل HTTP handler الفعلي مع socketpair خاص؛ الكود
القديم يفشل سبع حالات: EOF عادي، انقطاع upstream، فشل headers، وترك العميل،
ورفض طلب صريح، ورفض المصادقة بلا إعادة محاولة، وإعادة محاولة النموذج المجاني.
الإغلاق في finally ينجح فيها، والطرف الآخر يرى FIN أو reset. بوابة أخطاء
SSE القديمة ما زالت تمر. هذا ليس إثبات إلغاء provider ساكن قبل أي بيانات.

رسالة selfcheck كانت تعد TCP connections مشاهدين وتقرر أنها سبب البطء،
ثم تقترح stop لخدمة هي شاشة Oracle. الرسالة الجديدة تصف الاتصالات فقط،
توجه إلى مراجعة الأجهزة وتحافظ على شاشة المالك؛ لا تخفي فشلًا أو تضعفه.
fixture اتصال status واحد يثبت أن النص لا يدّعي صورة أو يوصي بقطع الشاشة.

مرت `just check` كاملة على المصدر النهائي ذي حالات الرفض؛ تمر بوابة SSE واختبارات الإغلاق السبع.
الكود القديم يفشل السبع بالسبب المقصود: بقاء مورد upstream مفتوحًا بعد رجوع relay.
الإصلاحات في المصدر والضوابط الخاصة؛ البناء المحلي وCI والتسليم الموقّع
والقبول المثبّت مراحل مستقلة يجب تسجيل نتيجتها قبل إعلان وصول الإصلاح.

## ما كشفه البناء الكامل

اندمج PR232 عند `b11f5aa2`، وبوابات مصدره وصور ARM/x86 في PR تمر. البناء
المحلي الكامل توقف في استخراج مصدر Plymouth برمز 141. تجربة المصدر
المثبّت نفسه في حاوية خاصة أثبتت 8,836 بايت صفرية بعد نهاية newc؛ أنبوب
4 KiB يعطي producer=-13 وconsumer=0، والملفات الـ27 تطابق استخراج الملف.
الإصلاح يكمل `rpm2cpio` ويتحقق من خروجه قبل تشغيل `cpio` على ملف مؤقت؛
أخطاء المصدر والأرشيف والمستهلك تبقى توقف البناء. أربع حالات تمر، والكود
القديم يفشل ثلاثًا. أُلغيت دورتنا الأولى 38391961158/38391840384 قبل الترقية؛
اندمج إصلاح الاستخراج في PR233 عند `1c321a53`: البناء المحلي الكامل `f8a036d610a5` وكل بواباته و15 hash تمر، وARM/x86 CI يمران. البناءان الآليان 38436548287/38436548500 أُلغيا قبل ترقية لإكمال دفعة منتقي الصور. التسليم الجديد لا يزال مطلوباً؛ مكتبة الإقلاع وبواباتها لم تتغير.

## جهاز NVIDIA والوصول الفعلي

التحقق المتصفحي لـTailscale اكتمل: قناتا المالك وroot تعملان، دون تغيير
كلمات المرور أو ACL. النظام الجاري `.1032`، digest `4bbb7e5b…`، والرجوع
الموقّع `.1029`، digest `eeeef743…`. جلسة العربية Wayland تقرأ 4K/60 Hz
و250%، UI2 Arena وGTK Breeze، ومدخل إعدادات واحد؛ 55 selfchecks تمر.
فحص post-update يعطي 54/1 لأن أمر نسختنا التشخيصي `plasmashell --version`
خارج جلسة عرض abort بالـPID 212400. Plasma الحقيقي PID 4184 وKWin 2232
لم يتوقفا. نُسب core بدقة وحُذف ذلك الملف وحده؛ السجل والفحص لم يُخفيا.

رد السحابة المباشر 200 خلال 1.469 s، SSE أول نص .912 s وDONE بعد .988 s؛
usage المبلّغ صفر. Hermes الاختباري 200 خلال 4.413 s، usage غير موجود.
عينة cgroups مدتها 30 s خلال عمل المالك: RAM PSI صفر، Code الكبير 4.77 GiB
منها 3.85 GiB file cache/.86 GiB anonymous. KWin/Plasma 9.06/9.65% من نواة
واحدة، وليس كامل 16 CPU. Lumen 5.23% بينما أربعة أجزاء PC تتحرك؛ screen
sync متوقف. لا وقف لإضاءة المالك بغرض تحسين رقم القياس. جدول GPU الرسومي
الكامل نحو 1.74–2.05 GiB و0–12%، بلا ادعاء خمول أو غياب تسرب طويل المدة.
القرص writable فيه 179 GiB متاحة، وRAM نحو 10 GiB متاحة وقت baseline.

النسخة المحلية النظيفة وفرع main على NVIDIA لحقا المصدر `b11f5aa2` بعد
فحص ancestry وغياب عمل منفرد؛ archive يحتفظ بالرأس القديم. مراجعة الفرع
المنفرد وجدت merge `407c1eed` وحده، وأصلحت منه bootstrap منتقي الصور.
الفرع ومساحات العمل الأخرى محفوظة. 34 API و12 native Qt اختبار تمر؛
منتقي KDE يظهر من bootstrap الحقيقي بالعربية والإنجليزية، والإلغاء يحفظ
المرفق/المسودة دون أي API request. المصدر القديم يملك صفر native widgets
ويفشل الضابط المقصود. Wayland NVIDIA يثبت المنتقي بالعربية والإنجليزية من المصدر، لا
من صورة جديدة مثبّتة. اختيار الصورة ورفعها في الإصدار الجديد، الاختبارات
الأوسع والتسليم الموقّع ما زالت حدود قبول منفصلة.

## قبول .1042 وعطل الإدخال قبل تسجيل الدخول

دورة c5f2451b اكتملت في المحاولة الأولى: بناء 38446133446، الأقراص
38454884448/38454887386/38454893061، ISO 38454900845، ترقية 38461170910،
وARM كامل 38445991140. latest للنسخ الأربع مطابق: x86 .1042 وARM .771.
NVIDIA أقلع .1042 فعلًا، مع رجوع .1032 الموقّع ومعرّف جديد، وفحوص UID 1000
55 selfcheck و55 post-update بلا فشل و16 ملفًا وبرنامج MoPlayer مطابقًا.
الإقلاع 36.174 ثانية؛ لا يُقارن بعينة سابقة كحكم سرعة عام. تحذير UCSI -110
للمنفذ USB-C باقٍ. Oracle .771 مجهّز رسميًا، وقبول الإقلاع لا يزال .763.

عند شاشة الدخول قال المالك إن Mo PC Remote لا يكتب. التشخيص أثبت أن الخدمة
كانت غير مفعّلة؛ فُعّل مسارها بطلب الدخول البعيد عبر TLS الخاص/PIN مستقل،
دون كلمة مرور الحساب أو تعديل PAM. ثم ظهر عطلان حقيقيان: بوابة KDE بدأت
دون KDE/Wayland في بيئتها، فلا تعرض واجهتي ScreenCast/RemoteDesktop؛ وبعد
تهيئتها أصبح EIS جاهزًا لكن secureText=false. خريطة جهاز KWin الفعلية
43505 بايت/ثلاث مجموعات de/us/ara؛ قيد المجموعة الواحدة يرفضها. قراءتها
المصححة تعطي 178/98/144 مدخلًا، دون قراءة أو إرسال أي كتابة/كلمة مرور.

إصلاح المصدر ينشر حقائق الجلسة حتى عند بقاء التحكم غير مفعّل، ويفحص واجهات
البوابة الفعلية عند التفعيل في جلسة قائمة، ويجدد بوابة حساب شاشة الدخول
الناقصة وحدها ويحذف سلطة التفعيل عند الفشل. تصحيح parser يطابق عدد مجموعات
EIS الفعلية ويحتفظ برفض الخرائط الغائبة/المخالفة. 15 فحص إدارة و14 فحص خريطة
أصلية وفحص المستودع الكامل وكل مشاريع/اختبارات .NET نجحت. القيود الخاصة
بالموافقة وPIN وTLS والملفات والحافظة قبل الدخول والمصادقة الأصلية باقية.
[مصدر KDE 6.7](https://github.com/KDE/xdg-desktop-portal-kde/blob/Plasma/6.7/src/desktopportal.cpp)
يؤكد اعتماد تصدير واجهات البوابة على XDG_CURRENT_DESKTOP؛ الفحص الحي هو دليل العطل.

على NVIDIA فقط نُسخت حزمة /usr/lib/mo-remote الموقّعة إلى
/var/lib/mo-remote-greeter/runtime-audit-20261013، مع استبدال helper Python
بهذا التصحيح المراجع. override مؤقت في /run/systemd/user عبر MO_REMOTE_AGENT
الذي يدعمه المشغّل القائم، وREADME خاص يذكر السبب والبصمة والتقاعد. لم يتغير
/usr أو أصل النظام أو إعداد الحساب، ولا يُعد ذلك إصدار OS موقّعًا. اتصال
اختبار مستقل/PIN جديد غير محفوظ كجهاز موثوق قرأ hello فقط: secureText أصبح
true، ولم يرسل مفاتيح أو نصًا أو فأرة أو حافظة. المالك أكد أنه دخل؛ logind
يؤكد Service=plasmalogin وWayland وحسابًا واحدًا، وRemote انتقل إلى نطاق الحساب.
بعد تسليم التصحيح موقّعًا وبصمة helper المطابقة، تزال فقط نسخة override
المملوكة، ثم النسخة المؤقتة بعد إثبات عدم وجود عملية تستخدمها. لا reboot
آخر لـNVIDIA قبل تسليم التصحيح أو ترتيب قناة دخول مناسبة.

MoPlayer المثبّت يفتح URI لاسم عربي، ويعلن مدة 20 ثانية/CanSeek، ويتقدم الزمن
ويقدم 5 ثوانٍ أثناء التوقف. RSS=784300 KiB، وجدول GPU الكامل يثبت 593 MiB
لعملية الفيديو ثم غيابها بعد Quit؛ ليست هذه قراءة compute-apps ولا إثبات
إطارات متحركة/HDR/كل codecs أو endurance. الذكاء المباشر ينجح في 1.02 ثانية،
والبث في 1.11 ثانية لأول محتوى/32 حدثًا/DONE بتكلفة مبلغ عنها صفر. Hermes
المعزول ينجح في 4.30 ثانية بلا usage؛ لا يُسمّى غياب usage تكلفة مقاسة صفرًا.
بعد ذلك RAM متاحة نحو 12 GiB وswap صفر، وGPU 1129 MiB/P8/12.6 W تحت Remote؛
هذه قراءة واحدة وليست تأهيل idle طويلًا. لا نموذج محلي أو تغيير مزود.
