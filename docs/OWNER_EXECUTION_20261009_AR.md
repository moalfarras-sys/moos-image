## Remote قبل تسجيل الدخول

المصدر v57 يضيف تفعيلًا صريحًا بصلاحية المدير، متوقفًا افتراضيًا، وبروفايل
خاصًا بشاشة الدخول. يمرّر الإدخال إلى جلسة greeter الأصلية عبر EIS؛ لا نسخة
PAM معدلة ولا autologin جديد ولا حفظ كلمة مرور حساب النظام. PIN مستقل ومخفي،
وStop يلغي ثقة greeter قبل الإيقاف، وOn لا يعيد التفعيل تلقائيًا. قبل الدخول
لا ملفات ولا clipboard ولا واجهات طاقة/إعدادات/صوت أو قائمة أجهزة للمشاهد.

VM خاص اجتاز إقلاعات باردة، صورة مفكوكة فعلًا، PIN وكلمة مرور خاطئة/صحيحة،
تسليم الجلسة والعودة بعد الخروج، وإلغاء listener والثقة مع حفظ بيانات الحساب.
نجحت المشاريع السبعة .NET ومراجعات AR/EN والصورة المحلية الكاملة و31 بصمة.
فحص Oracle الحقيقي قبل/بعد يقبل Community العامة المنفصلة وRemote الخاصة
ويرفض نشر Remote بأي منفذ/مسار دون تغيير ingress. الكمبيوتر يجتاز أيضًا
شرط المسار الخاص وHTTPS بالشهادة الصحيحة دون تفعيل greeter. إعداد TLS للـgreeter في
VM كان fixture صريحًا؛ التفعيل الفعلي على TLS خاص، حسابات متعددة، الهاتف/WAN
وقبول NVIDIA الموقّع ما زالت أدلة مطلوبة P2.17. إقلاع ARM `.756` أثبت الملفات
والخدمات، ولم يفعّل الميزة أو يختبر دخول PAM بدل autologin الحالي.

## فحص EFI الحقيقي

الفحص خارج التركيب وجد علامة إغلاق غير نظيف فقط. بعد تجربة نسخة معزولة،
تغير بايت 65 وحده، ونجح fsck الخارجي وطابقت بايتات القسم نتيجة النسخة.
بصمات ملفات الإقلاع الـ16 محفوظة، وأُعيد مسارا vfat الحقيقيان، ثم حُذف 1 GiB
من نسخ الاختبار الخاصة. قبل ذلك أخطأت الأداة باعتبار المسارين مستقلين؛
الفصل انتقل بينهما فتوقف العمل قبل fsck، وأُصلح التركيب الصحيح. اختبار
خاص أعاد الخطأ وأثبت التصحيح؛ الأدلة الفاشلة باقية. قراءة الإقلاع البارد
التالي لازمة قبل الادعاء باختفاء التحذير عند الإقلاع.

## قياس الذاكرة الحالي

قياس 30 ثانية أثناء عمل المالك وجد 6.4–6.7 GiB متاحة، PSI=0، وكرت الشاشة
0–21% مع 1.62–1.81 GiB VRAM. أدوات التطوير والمتصفح أكبر الحمل النشط.
Baloo كان خاملًا مع 303,766 ملفًا وبلا انتظار/فشل؛ بعد إعادة تشغيل خدمته
وحدها انخفض PSS من 2,339,454 إلى 106,481 KiB، والذاكرة المجهولة من 993,344
إلى 13,620 KiB. الفهرس ووثيقة بحث فعلية وإعداداته محفوظة. هذا تحسين محلي
مقاس بعد الفهرسة، لا سياسة دائمة أو إثبات أداء أجهزة ضعيفة؛ جزء من PSS
السابق صفحات ملف قابلة للاسترجاع. المراقبة الطويلة وميزانيات P5.4 باقية.

## مركز المشاركة

اختار المالك: بلاغات خاصة مع الفريق، واقتراحات عامة اختيارية، وصورة يختارها
ويراجعها قبل الإرسال. لا غرفة عامة افتراضية ولا تصوير/نشر تلقائي.
العميل الأصلي مدمج في الصورة المشتركة للنسخ الأربع؛ الخادم على Oracle.
العنوان الحالي `https://moos-oracle.tailab78a5.ts.net:10000` منشور عبر
Tailscale Funnel وTLS، وله تسجيل حساب مفتوح. هذا مختلف عن الملفات والصور
وIDE وRemote الخاصة بالمالك؛ هذه تبقى عبر tailnet. النطاق المخصص باسم MoOS
ودورة دعم عامة مكتملة ما زالا مطلوبين.

نجحت 34 حالة API و11 حالة Qt أصلية، عزل حسابين وصور، outbox وإعادة محاولة،
رفض header مزوّر، رد/إشعار مرتبط بصورة نظام معتمدة وTLS/Wayland حقيقي.
الخادم root-managed بحساب غير مميّز، كود يملكه root، بيانات 0700 وUID namespace
الحقيقي؛ لا سر أو إعداد شخصي يُنشر في status. كل حسابات/صور الاختبار أزيلت.
بعد إعادة تشغيل Oracle خدمة `moos-community` نشطة، UID 968 ضمن namespace
المضيف، و`/v1/health` تعيد ready. واجهات hide/ban/delete الأساسية موجودة.
المتبقي P6.9: DNS مخصص، onboarding واسترداد وواجهة مراجعة كاملة وretention،
تفضيلات إشعارات، إتاحة وendurance، ثم إصدار مثبت يصل للمستخدمين.

## استضافة MoOS وحادث Vercel

الحساب Hobby فعّال ماليًا؛ التعطيل المؤكد من `fluidCpuDuration` ضمن fair-use،
10 أكتوبر 01:50 بتوقيت برلين. المواقع الأساسية للمشاريع الـ14 عادت عبر
unpause الرسمي، لكن counters وحظر deploy الجديد لم يُمحيا. 24/25 عنوانًا
تعمل؛ رابط A&D القديم متوقف ونطاقه الرسمي يعمل. أحدث Pünktlich له مشكلة
صلاحية Git-author مستقلة؛ الإنتاج الأقدم يعمل. 28 مراجعة متصفح فعلية نجحت
في عرض الصفحات؛ لم تُرسل طلبات/نماذج العملاء أو تدخل حساباتهم.

MoOS مستقل الآن: واجهة AR/EN وملفات/خطوط static على Cloudflare، ISO عبر R2،
وخدمات ميرا والمشاركة على Oracle. خمسة تحويلات CDN scoped على Vercel تحفظ
روابط MoOS القديمة فقط. لا CMS/ISR/optimizer/beacon لـMoOS، ولا تغيير ملكية
MoPlayer/admin/APIs. تحويل الدخول الصغير ما زال request على Vercel؛ الخدمات
المجانية لها حصص منفصلة ولا ضمان بأنها بلا حدود.

حُذف ISO سبتمبر من Blob بحجم/ETag مؤكدين، وبقيت ملفات MoPlayer الخمسة:
333,653,409 bytes. حُذفت مفاتيح R2 الثلاثة للنسخة `.1011` فقط بعد 410 وقراءة
الإصدار العام الحالي. `.1026` الآن منشورة ومثبتة عامًا عند 21:24:17 UTC: كامل
SHA-256 والتوقيع والـsidecars والاستئناف، مع manifest/proof متطابقين وصفحة منشورة.
نجحت ثماني مراجعات محلية وثماني عامة و14 فحصًا جديدًا للروابط/البيانات/الاستئناف عند 00:56:52 برلين. انتهت مهلة `.1018` وحُذفت
مفاتيحها العامة الثلاثة فقط عند 17:05:09 برلين (5,808,128,179 bytes)، بعد
إعادة تحقق مستقلة. `.1022` تبقى متاحة حتى 12 أكتوبر 14:00 برلين؛ timer دائم
للتقاعد الساعة 14:05 يجتاز خمس حالات رفض دون حذف حالي. العامل يجتاز 21 اختبارًا.
ISO الجديدة محفوظة على Oracle؛ أرشيف التنزيل المؤقت حُذف بعد الاستخراج الصحيح
على القرص بحد RAM=768 MiB. حُذفت ملفات ISO `.989` المحلية الثلاثة فقط بعد
SHA كامل وancestry وعدم وجود مستهلك؛ 5,786,763,443 بايت. المتاح المقاس نحو
165.6 GiB على الكمبيوتر و30.9 GiB على Oracle؛ بيانات العمل والرجوع محفوظة.

الحسكة مشروع مستقل، ودخلت الفحص فقط ضمن طلب إعادة مواقع Vercel؛ ليست
اعتمادًا لـMoOS، ولم يُربط حسابها أو تُعدّل بياناتها. تعثّر صور Supabase بسبب
egress quota باقٍ في سجل حادث المواقع؛ أوقف المالك متابعة هذا المشروع ضمن
تطوير MoOS. فحص ساعة واحدة وجد 27 فشل upstream في image proxy لـMoPlayer
(15×502، 12×504)، فلا نعد HTTP200 للواجهة سلامة لكل API. تفاصيل الموقع
والتشغيل في مستودع Mohammad-alfarras، PR56 المدموج عند `11cb5052` و
`docs/MOOS_FREE_HOSTING.md`؛ المصدر ينجح بمهام GitHub الثلاث، وحظر معاينات
Vercel باقٍ ومرئي.

بعد نجاح مصدر الموقع ومراجعته العامة حُذفت ستة مجلدات اختبار مولّدة من
worktree الموقع فقط: 1,263,339,069 بايت منطقي. المصدر والـlockfiles واعتماديات
المستودع الأصلي محفوظة. بسبب CoW وبناء الصورة المتزامن لا نساوي هذا الرقم
بمساحة قرص فعلية مسترجعة ولا نزعم أن قراءة المساحة السابقة ما زالت الحالية.

## الاستئناف

1. اقرأ AGENTS.md والمهارة الإلزامية وPROJECT_STATE والخطة؛ حدّد الجهاز أولًا.
2. fetch current refs وراجع المرشح/CI/العمل غير الملتزم قبل الدمج. worktrees
   منفصلة؛ لا مصدر متحرك داخل دورة إصدار ولا تعد مصدرًا محليًا إصدارًا رسميًا.
3. NVIDIA autostart الخاص `post-owner-batch.py` يقرأ digest/boot ID/rollback
   وبصمات الملفات والفحصين في سياق الجلسة الأصلية، ويزيل نفسه بعد قبول فعلي.
4. Oracle يستخدم الآن native SSH بمفتاح محطة خاص وبصمة خادم متحققة، خدمة user
   تعيد اتصال master تلقائيًا؛ لا تغيير حماية SSH العامة أو Tailscale policy.
   نفّذ قبول desktop عبر transient user unit يرث بيئته الأصلية، لا SSH fallback.
5. أدلة raw والاعتماديات السرية تبقى خارج Git في مجلد audit الخاص. افحص خدمة
   نقل/نشر R2 قبل أي reboot؛ ملفات المرجع الثلاثة فقط، دون نسخ ISO مكرر في RAM.
6. حدّث الحالة والخطة من النتيجة الفعلية، احفظ وادفع العمل. مصدر جديد يحتاج
   دورة RELEASE.md جديدة قبل التسليم؛ لا تضع علامة «جاهز بالكامل» على بند ناقص.
