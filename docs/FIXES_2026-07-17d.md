# 2026-07-17 session J — Plasma IS MoOS: taking the greeter's own components

The owner's directive, and it is the whole design of this change:

> بدي شاشة بلازما نفسها نطورها نحدثها نخليها MoOS … ما في شي مركب عليها او مخفي
> … ما تخفي شي ما تغطي شي او تقفل شي … ما تصمم شي جديد بس الي موجود يتجمل

Take Plasma's own screen and make it MoOS. Nothing layered on top, nothing
hidden, nothing covered, nothing switched off. Do not design a new thing —
beautify what is already there.

## What was wrong

The login screen was half MoOS. Its wallpaper is the branded scene (the mark,
the comet ring, "أهلاً بعودتك"), but the moment the user touches it the auth card
is stock Breeze: a Breeze clock in DemiBold with one English date, and
Sleep/Restart/Shut Down as full-colour discs — the exact class of off-brand icon
session F fixed on the LOGOUT screen ("isMask over full-colour disc icons"),
sitting two seconds before that same logout screen shows the same actions as
monochrome teal glyphs.

And the clock had been **hidden** (`ShowClock=false`, 2026-07-16) precisely
because it could not be re-skinned. That is the workaround the owner's directive
strikes down.

## What the previous reasoning got wrong

The shipped comment said the greeter's face "cannot be re-skinned from the
filesystem" because its QML is compiled into the binary
(`qrc:/qt/qml/org/kde/plasma/login/Main.qml`). The premise is half true and the
conclusion was wrong.

`Main.qml` IS compiled in — but it only INSTANTIATES `BreezeComponents.Clock`
and `BreezeComponents.ActionButton`. That module,
`/usr/lib64/qt6/qml/org/kde/breeze/components/`, is ordinary QML on disk, owned
by plasma-workspace, and Plasma resolves it by import path. It is also what the
LOCK screen and the LOGOUT screen draw from. One module, three doorways.

So no C++ rebuild of plasma-login-manager was needed — that was the plan for an
hour, and reading the module first killed it.

## The trap that would have shipped a green build and an unchanged screen

Overwriting those .qml files does nothing on its own. The module's `qmldir`
carries:

    prefer :/qt/qml/org/kde/breeze/components/

which points Qt at copies **AOT-compiled into libcomponents.so** (the symbols are
right there in the .so) and makes the on-disk .qml files decoys.

MEASURED, in a harness rendering the real components: MoOS's `ActionButton.qml`
and `Clock.qml` first in the import path, `prefer` intact → **stock Breeze
rendered anyway**. Same files, `prefer` dropped → the MoOS face appeared. A gate
reading those .qml files would have been green through every bit of that.

`build.sh` now drops the line, fail-loud: if plasma-workspace ever stops shipping
it (or the module moves) the build stops, rather than the login screen quietly
reverting to Breeze on a base bump.

## What MoOS's components do

`ActionButton.qml` — same id, same API (text, icon.name, clicked, animateClick,
mnemonics, softwareRendering fallback), so the compiled greeter, the lock screen
and the logout screen cannot tell the difference:
- `symbolicName()` maps the name the greeter asks for onto its -symbolic glyph,
  and `isMask` paints it in the brand colour.
- Shut Down alone is destructive-red — matching MoOS's logout screen exactly.
- The circle is MoOS glass with the hairline every other MoOS surface carries.
- IBM Plex Sans.

`Clock.qml` — upstream's ENGINE kept (`PlasmaClock.Clock` handles timezone and
resume correctly); only the face changed, to the one the lock screen and the Hero
Clock already wear: light-weight HH:mm, a colon breathing in the brand colour,
the turquoise tick, and the date in Arabic then English. And so `ShowClock=true`
— the clock comes back, because MoOS owns the surface now instead of hiding it.

## Two bugs the live render caught (neither was visible in the code)

1. **A solid teal blob where "Other…" should be.** `system-user-prompt` has no
   -symbolic variant, so it was mapped to `user-identity-symbolic` — which reads
   perfectly and is a FILLED disc, so masking it produced a blob with no glyph.
   Every candidate was then rendered side by side under isMask and chosen by
   looking: `user-symbolic` for the prompt, `system-users-symbolic` for the list.
   The name is not evidence; the picture is.
2. **Two red buttons.** Restart was marked destructive alongside Shut Down. Side
   by side they read as an alarm, and they disagreed with MoOS's own logout
   screen, where only Shut Down is red. One system, one language.

## Gates (in `verify_image_experience.py`, which runs INSIDE the image)

- `org.kde.breeze.components/qmldir` must have NO `prefer` line — the decider,
  not the decoys.
- `ActionButton.qml` and `Clock.qml` must be present there AND be MoOS's.
- `ShowClock=true` — a MoOS-branded surface must not be hidden.
- THEME_REV → 19, because Qt's qmlcache keys on mtime and OSTree pins every mtime
  under /usr to the epoch: without the bump an upgraded machine keeps executing
  the stale compiled components. (This is the trap Mo AI already hit once.)
